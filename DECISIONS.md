- [picker-latency-and-contrast-2026-08-13]: `<leader>f` went 601ms -> 36ms; the picker no longer dims the screen
  - **The delay was not the picker.** `<leader>f` shared its prefix with fourteen longer mappings (LazyVim's whole file/find group), so nvim waited out `timeoutlen` -- 500ms, inherited from lvim -- on every press before it was allowed to run the short mapping. Measured as 601ms total = 516ms waiting + 85ms opening. The group moved to `<leader>F` key for key (`lua/plugins/picker.lua` disables the eleven spec-defined ones; `lua/config/keymaps.lua` deletes `fn`/`ft`/`fT`, which LazyVim sets directly and `false` cannot reach). Rule to keep: nothing longer may ever share the `<leader>f` prefix.
  - **The remaining 85ms was `fd`.** `~/.cargo/bin/fd` is 8.5.3 from Nov 2022 and needs 70-85ms to list 400 paths; `rg --files` does it in 20ms, and snacks' Lua matcher is 1.3-4.3ms for 5,342 paths. So the "backing search" was already native tooling -- fzf-lua would have changed nothing but the look. `sources.files` now asks for `rg` when it exists. Neither `fd` nor `ripgrep` is declared in `modules/darwin/homebrew.nix`; declaring a current `fd` there would fix this for every tool on the machine, and Homebrew's bin dir precedes both `~/.cargo/bin` and the Nix profile on PATH.
  - **Too dark had two causes.** snacks.win's default `backdrop = 60` dims everything behind a float, and the `default` picker layout is the only preset that does not turn it off -- measured as Normal's `#1D1F21` dropping to `#111213`. Separately the picker paints its four windows through `SnacksPicker{,List,Input,Preview}`, which default to `NormalFloat` (`#1A1C1D`), a shade below Normal. lvim's telescope measured `#1D1F21` throughout. Fixed by `layout.layout.backdrop = false` plus four links in the parity table in `lua/config/autocmds.lua`.
  - **The visual and perf harnesses were removed** at the operator's request, along with the recorded lvim baselines. Re-deriving any of this now means re-instrumenting from scratch, and lvim disappears at the cutover; the findings live in `NOTES.md` under "Looking like lvim" and in this entry.
