- Both installations read the same key store at ~/.gnupg (pubring.kbx, trustdb.gpg,
  private-keys-v1.d/). Confirmed by listing secret keys with both binaries and
  getting identical output. The currently running gpg-agent process (pid 56889)
  was launched against `--homedir /Users/CASE/.gnupg`, so the agent is shared too.
- gpg --version is 2.4.8 on PATH (>= 2.2 required by D10). MacGPG2 fallback is 2.2.41,
  also >= 2.2. Both satisfy the D10 modernity floor.
- Public keys (`pub` entries): 104. Many are imported keybase.io social-graph
  keys from 2014–2019; ~40 are expired and would not be brought forward in a
  clean Nix-managed home. They are signature-verification trust anchors and are
  not security-sensitive, but are stale.
- Secret keys (`sec` entries): 1. Fingerprint
  2848EFB300F361FD6D770DC0715CED2327899E28 (suffix 715CED2327899E28). This is
  the D10 signing key. Capability is [SC] (Sign + Certify) on the primary plus
  an [E] encryption subkey. There is exactly ONE signing-capable secret key.
- Anomaly 1: `~/.gnupg/gpg.conf` sets
  `default-key 099A18D55F20E2E810EE960EDFAED45206F8A9FA`, a fingerprint that is
  NOT present in the public or secret keyring on this machine. Effectively a
  no-op today (gpg falls back to the only available secret key), but the
  declarative `programs.gpg`/`services.gpg-agent` config should either drop
  `default-key` or set it to the D10 fingerprint
  `2848EFB300F361FD6D770DC0715CED2327899E28`.
- Anomaly 2: `auto-key-locate keyserver hkps://hkps.pool.sks-keyservers.net` —
  the SKS pool was deprecated in 2019 and the hostname no longer resolves.
  `dirmngr.conf` already points at `hkps://keys.openpgp.org`; the gpg.conf
  keyserver line is stale and should be removed or aligned.
- Anomaly 3: `S.gpg-agent.ssh` socket exists in ~/.gnupg even though D10 says
  `services.gpg-agent.enableSshSupport = false`. The socket is a Home Manager /
  gpg-agent default, harmless when SSH support is off but worth verifying the
  generated Nix config does NOT set `enable-ssh-support` in gpg-agent.conf.
- Anomaly 4: Many keys in the public ring are very old (dsa1024 from 2005,
  rsa2048 from 2010–2013) and several are expired. Not load-bearing for D10.
- Anomaly 5: Existing `~/.gnupg/gpg-agent.conf` hardcodes
  `pinentry-program /opt/homebrew/bin/pinentry-mac`, which is the Homebrew
  cask `pinentry-mac` path. D5 expects `pinentry-mac` to remain a Homebrew
  bridge dependency, so this is consistent. The declarative
  `services.gpg-agent.pinentryPackage` (or equivalent) must point at the same
  binary so the value reproduces after switch.
- `default-cache-ttl 600` / `max-cache-ttl 7200` should be carried forward into
  the Home Manager `services.gpg-agent` config to preserve current UX.

  and it matches the D10 fingerprint.
